# Маршрут

Русский сетевой клиент для **Windows 10/11 x64** и **Android 10+ arm64 без root**:
VLESS, DPI-обход zapret и резервный маршрут Cloudflare WARP.

**[Скачать Windows 0.1.7](https://github.com/ivantolm2004/marshrut/releases/download/v0.1.7/Marshrut-0.1.7-Windows-x64-Setup.exe)** ·
**[Скачать Android 0.1.6](https://github.com/ivantolm2004/marshrut/releases/download/v0.1.6/Marshrut-0.1.6-arm64.apk)** ·
[Все релизы](https://github.com/ivantolm2004/marshrut/releases)

На Windows нужен только один установщик EXE. В приложении укажите свой
VLESS-ключ или подписку; дополнительные папки, Go, Flutter и отдельный WARP
для установки не нужны. [Инструкция](docs/INSTALL-RU.md).

Тестовая версия: фактически выполненные проверки и ограничения описаны в
[BUILD-REPORT.md](BUILD-REPORT.md). Android после исправления подключения
требует полевой проверки на устройствах.

## Как пользоваться

1. Установите соответствующую сборку. Windows-установщик создаёт службу;
   Android при первом подключении запрашивает разрешение VPN.
2. В разделе «Серверы» вставьте `vless://`, HTTPS-подписку, Base64-подписку или
   JSON sing-box. Можно добавить несколько собственных серверов.
3. WARP настраивается в фоне автоматически через неофициальную библиотеку wgcf.
   При недоступности регистрации напрямую приложение повторит попытку после
   подключения через VLESS. Условия Cloudflare и выключатель автонастройки
   находятся в «Настройках»; готовый WireGuard-профиль можно импортировать вручную.
   Новый профиль применяется при следующем подключении и считается рабочим
   только после проверки туннеля и выхода WARP.
4. Нажмите «Подключить». До завершения проверок маршруты не объявляются рабочими.
5. В «Серверах» нажмите «Пинг серверов», затем оставьте «Автоматически» либо
   выберите конкретный VLESS-сервер. В автоматическом режиме проверяется небольшая
   группа кандидатов, а не вся подписка. TCP-пинг не подтверждает работу VLESS.
6. В «Правилах» оставьте автовыбор либо закрепите нужный сервер для сервиса.
   AI-сервисы при наличии рабочего VLESS используют его в первую очередь.
7. «Диагностика» показывает результаты TLS, UDP/STUN и проверки WARP. Тест
   скорости запускается отдельно и загружает 2 МиБ.

Для YouTube, Discord и Telegram zapret выбирается при успешной проверке и меньшей
задержке, чем у VLESS. AI-сервисы и неизвестные внешние назначения сохраняют
приоритет VLESS. WARP — резерв при отсутствии рабочего VLESS, даже если его
задержка меньше. Ручное закрепление имеет приоритет. Проверяется задержка,
а не пропускная способность; переключение затрагивает новые соединения.

Windows-установщик включает запуск интерфейса при входе владельца в систему.
Его можно выключить в «Настройках»; выбор сохраняется при обновлении.
Android по умолчанию восстанавливает ранее включённый VPN после перезагрузки,
если уже выдано системное разрешение VPN. После ручного отключения VPN
не восстанавливается. Автозапуск также отключается в «Настройках».
Первое разрешение VPN требует действия пользователя; ограничения прошивки
могут дополнительно влиять на фоновый запуск.

В соответствии с выбранными настройками при отказе туннелей разрешён прямой
резерв. При его использовании сервис видит IP вашего провайдера. Этот режим
можно отключить. Локальная сеть остаётся доступной напрямую.

На Android действует один VPN-сервис. Официальное приложение WARP не нужно
включать одновременно с Маршрутом. Полный nfqws/zapret без root не реализуется:
tpws работает только с TCP, UDP получает самостоятельный маршрут. TLS/STUN
подтверждают работу транспорта, но не заменяют проверку видео и реальных звонков.

Если Android-приложение завершилось при подключении, откройте его снова,
зайдите в «Диагностика» и нажмите «Скопировать отчёт». Версия 0.1.5 показывает
этап запуска VPN, системный код предыдущего завершения и категорию нативного
сбоя, имена функций из стека и время нативного файла. Версии APK и общего
ядра указываются отдельно. Сохранённый SIGSEGV без совпадения времени ещё
не доказывает причину последнего завершения. Отчёт не содержит ключей,
подписки, аргументов стека или исходного текста crash-файла.
Для Samsung S25 FE сохранён обход графического сбоя и включён Android-обход
стека сетевых обратных вызовов sing-box; проверка на телефоне ещё требуется.
В 0.1.6 исправлен обнаруженный по стеку сбой определения владельца соединения:
адаптер возвращает настоящий объект или ошибку, вместо null, который приводил
к падению sing-box при первом трафике TUN. Установите APK поверх предыдущей
версии с сохранением подписки и повторите подключение.

## Сборка

Требуются Go 1.26+, Flutter 3.47.7, Python 3.11+, Git. Для Windows
нужны Visual Studio с C++ Desktop **или** переносимый LLVM/MinGW. Установщик
собирается на Go; Inno Setup не требуется. Для
Android — JDK 17, Android SDK 36, build-tools 36.0.0 и NDK 28.2.13676358.

```powershell
# Общее ядро, тесты и Windows CLI-служба
.\scripts\build.ps1 -Target Core -Go 'C:\tools\go\bin\go.exe'

# Нативный интерфейс Windows и установщик
.\scripts\build.ps1 -Target Windows -Flutter 'C:\tools\flutter\bin\flutter.bat' `
  -LlvmRoot 'C:\tools\llvm-mingw'

# Android: ключ подписи должен оставаться у владельца приложения.
$env:MARSHRUT_KEYSTORE = 'C:\private\marshrut-release.jks'
$env:MARSHRUT_KEY_PASSWORD = '<пароль вашего ключа>'
.\scripts\build.ps1 -Target Android -AndroidSdk 'C:\tools\android-sdk' `
  -JavaHome 'C:\tools\jdk17'
```

В исходники включены Flutter runners с нативными адаптерами. Скрипт
собирает AAR и помещает результаты в `release/`. Секреты подписи передаются через
окружение, не через командную строку компилятора. Не добавляйте keystore и пароли
в исходники. Сохраните ключ для установки будущих APK поверх текущей версии.

Список закреплённых компонентов: `components.lock.json`. Go-зависимости
фиксируются в `core/go.mod` и `core/go.sum`. Android-сборка отключает сохранение
открытого диагностического снимка конфигурации в libbox и добавляет защиту
сокетов tpws **до** вызова `connect()`.

## Устройство проекта

- `core/profile` — строгий импорт VLESS, подписок и WireGuard. Неподдерживаемые
  параметры сообщаются явно; неизвестные команды WireGuard не исполняются.
- `core/engine`, `core/probe`, `core/route` — конфигурация sing-box, TLS/STUN,
  проверка WARP и переключение маршрутов после трёх ошибок с паузой 60 секунд.
- `core/app`, `core/mobile`, `core/ipc` — общие команды и платформенные мосты.
- `core/platform/windows` — встроенное ядро sing-box и контролируемый zapret2.
- `ui/lib` — русский интерфейс с пятью разделами.
- `platform/android` — VpnService, Keystore и защищённый канал сокетов tpws.
- `core/cmd/marshrut-setup` — самостоятельный установщик и удаление службы;
  `platform/windows` — вспомогательные сценарии ручной установки.

Windows IPC использует именованный канал с ACL для владельца и SYSTEM и
отклоняет удалённых клиентов. Локальные тестовые SOCKS-порты требуют случайный
пароль. Android-секреты шифруются AES-GCM ключом Keystore, Windows — DPAPI
контекста службы. Персональная подписка не входит в код и установочные пакеты.
Windows-установщик не имеет подписи Authenticode. APK подписан отдельным личным
ключом проекта; резервная копия ключа хранится отдельно от исходников и сборок.

Нативный tpws поставляется как PIE-помощник `libtpws.so` в защищённом каталоге
нативных библиотек APK. Отдельный процесс сохраняет стандартную обработку
сигналов и seccomp tpws. Перед каждым внешним `connect()` помощник передаёт
реальный сокет VPN-службе через SCM_RIGHTS и получает подтверждение `protect()`.
При ошибке защиты соединение закрывается. Прямого запуска загруженных файлов
из доступного для записи каталога приложения нет.

## Проверки

```powershell
cd core
go test -tags 'with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api' ./...

# Необязательные сетевые проверки не изменяют системные маршруты.
$env:MARSHRUT_NETWORK_TEST='1'
$env:MARSHRUT_TEST_SUBSCRIPTION='<ваша HTTPS-ссылка>'
go test -v -tags 'with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api' `
  ./profile ./platform/windows
```

Подписка в тестах передаётся только через окружение. Вывод содержит количество
профилей и успешных проверок, без адресов серверов и ключей. Матрица испытаний
перед повседневным использованием: `docs/acceptance.md`.

## Обновления

Компоненты обновляются вручную новой проверенной сборкой. Автоматическая
загрузка и исполнение произвольных Lua-стратегий отсутствуют. Сетевые компоненты
должны соответствовать установленному манифесту SHA-256. При изменении версии
необходимо повторить конфигурационные и платформенные проверки.
