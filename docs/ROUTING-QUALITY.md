# Цель: удобная и надёжная маршрутизация

Активная цель пользователя: довести маршрутизацию до идеала. Уточнённый
приоритет — удобство настройки приложений и сайтов; пользователь предложил
общую базу сайтов, IP-адресов и приложений. Предпочтения сохраняются: игры
напрямую по умолчанию, индивидуальный VPN вручную, автоматическое обнаружение
приложений, без приписки с названиями игр в заголовке, без Computer Use.

## Требования для проверки завершения

- Общий локальный каталог приложений, сайтов, сервисов и сетей; встроенные,
  обнаруженные и пользовательские записи различаются и доступны через поиск.
- Простой ввод сайта обычной ссылкой, IP или подсети; понятная нормализация,
  проверка ошибок и отсутствие выдуманных адресов/массовых списков общих CDN.
- Быстрое назначение маршрута из строки каталога, сохранение пользовательских
  изменений, отсутствие дублей и случайного изменения общих правил программ.
- Прозрачные приоритеты и возможность узнать, какое правило сработает для
  приложения/сайта, отдельно для TCP и UDP. Предпросмотр не выдаётся за реальное
  измерение работающего сетевого потока.
- Сохранённые и применённые изменения различаются; только изменения, влияющие
  на маршрутизацию, требуют применения. Неудачное применение не должно оставлять
  пользователя без прежней рабочей конфигурации.
- Согласованные правила DNS и соединений; корректные блокировки и отсутствие
  прямого резерва у явно выбранного VPN. Локальная сеть сохраняет своё правило.
- Импорт, экспорт, переименование, отключение и удаление не повреждают данные;
  параллельные изменения не перезаписываются молча.
- Миграция существующих правил и обнаруженных приложений без потери данных.
  Подписки и VPN-ключи остаются в DPAPI-хранилище; личные пути и условия правил
  не появляются в диагностических отчётах.
- Проверки ядра, транзакций и восстановления БД, интерфейса на узком/широком
  окне, нативного запуска и установленной версии. Маршрутизация проверяется
  соответствующими сетевыми тестами; зелёные тесты формы не доказывают работу TUN.

## Архитектурное решение текущей итерации

Локальная SQLite с зашифрованным снимком каталога и правил существующим DPAPI-кодеком.
Каталог и пользовательские правила изменяются транзакционно. Старый JSON
настроек импортируется один раз и остаётся источником VPN-профилей и прочих
параметров. Успешные изменения правил по возможности отражаются в старом
хранилище для совместимости; ошибки такого зеркалирования сообщаются отдельно.
Служебные обновления обнаружения приложений записываются только в БД, не меняют ревизию пользовательских
правил и не заставляют закрывать открытый редактор.

SQLite хранит один зашифрованный снимок: правила, записи каталога и метаданные
приложений фиксируются одной транзакцией BEGIN IMMEDIATE. Поиск выполняется
по расшифрованному снимку в памяти; выбран такой формат для небольшого локального
каталога, а не для SQL-запросов по персональным путям и доменам. Чтение будущей
версии схемы или повреждённой базы завершается ошибкой без сброса данных.

В этой итерации реализованы: каталог с источниками и типами, быстрый выбор
маршрута с поиском серверов, добавление ссылок/IP/CIDR, редактирование названий
и простых адресов, удаление, объяснение отдельных и совместных совпадений
приложения с сайтом для TCP/UDP. Имена и категории исключены из сравнения
действующих маршрутов. При ошибке запуска новых правил предпринимается запуск
предыдущего снимка; явное отключение пользователем отменяет восстановление.

Перенос каталога в JSON включает сохранённые записи, отключённые условия и
упорядоченный список правил. Импорт проверяет схему, условия и ревизию перед
одной транзакцией. Проверено восстановление неактивной записи после открытия БД
и сохранение вставленного JSON в форме при конфликте.

Проверены DNS по TCP и UDP, приоритет сайта и приложения, пересечения условий
по протоколам, UDP-маршрутизация и отказ при недоступном пути. В изолированном
Windows TUN прошли DNS с владельцем сокета, TCP по домену и UDP по пути EXE.
Временный маршрут удалился, снимки маршрутов по умолчанию совпали. Сценарии
с общим системным DNS-брокером и реальные игровые матчи требуют полевой проверки.

## Исходное состояние и найденные недочёты

Проверена установленная 0.1.9: служба отвечает, 31 правило, каталог обнаруженных
EXE работает. Код текущей рабочей ветки является источником истины. В исходном
интерфейсе для изменения одного маршрута приходится открывать длинную форму;
ссылки с https:// отклоняются; нет общего каталога и объяснения совпадений.
Имена/категории меняют ревизию и ошибочно требуют переподключения; после ошибки
применения прежняя конфигурация автоматически не восстанавливается. Проверки
реальных игровых сессий и всего TUN-пути не заменяются существующими тестами.

Цель остаётся активной, пока требования не подтверждены соответствующими
артефактами и проверками. Удобный каталог — часть цели, а не её новое определение.
