# Совместимость Windows: тестовая сборка

Пользователь вставляет свою подписку или VLESS-ссылку и нажимает
«Подключить». Формат и подходящее ядро определяются автоматически. В выборе
сервера по умолчанию остаётся «Автоматически». Параметры удалённого сервера
берутся из подписки: приложение не подбирает UUID, SNI или ключи REALITY.

## Что добавлено

- VLESS URI, обычные и Base64-подписки, JSON sing-box, распространённые
  VLESS-конфигурации Xray JSON и VLESS-узлы Clash YAML/JSON.
- RAW как синоним TCP, WebSocket Early Data (`ed`, `eh` и `?ed=` в path),
  известные имена-синонимы параметров и безвредные поля названия/группы.
- Обычные TCP/REALITY, WS, gRPC gun и HTTPUpgrade обслуживает sing-box.
  XHTTP/SplitHTTP, gRPC multi, нестандартный spiderX REALITY и VLESS Encryption
  автоматически направляются через комплектный Xray. Поддержку конкретных
  параметров подтверждает предварительная проверка настоящим ядром.
- XHTTP: auto, packet-up, stream-up, stream-one; path, host и ограниченный набор
  extra: noGRPCHeader, noSSEHeader, scMaxEachPostBytes, scMinPostsIntervalMs,
  scMaxBufferedPosts, scStreamUpServerSecs, xPaddingBytes, headers, xmux.
- Если сервер подписки возвращает неподдерживаемый формат/веб-страницу,
  Windows повторяет запрос с идентификаторами v2rayN и Clash.Meta. Суммарный
  срок запроса ограничен 30 секундами. Ошибки авторизации и сетевые ошибки не
  обходятся. Рабочая сохранённая конфигурация при неудаче остаётся на месте.
- Каждый сервер отдельно проверяется до запуска общей конфигурации.
  Некорректные узлы пропускаются с предупреждением по номеру. Ручной выбор
  несовместимого сервера выдаёт ошибку с предложением включить автовыбор.
- При неудаче первой группы автовыбор сразу проверяет до двух следующих групп
  по три сервера. Монитор продолжает ротацию; уже рабочий маршрут сохраняет
  прежнюю защиту от частых переключений. TCP-пинг не считается проверкой туннеля.
- Локальные порты выбираются из свободных, чтобы уменьшить конфликты с
  другими программами. Если порт успела занять другая программа, запуск
  повторяется с новыми портами до трёх раз. Xray запускается без видимого окна, получает настройки
  через stdin, связан с жизненным циклом службы и останавливается при отключении.
- Xray привязывается к исходящему адаптеру до создания TUN, адреса провайдеров
  предварительно разрешаются. При изменении сети соединение с Xray пересоздаётся.
  Локальный мост слушает только 127.0.0.1 и требует случайные реквизиты SOCKS.

## Границы поддержки

Абсолютная совместимость со всеми провайдерами не обещается. Закрытые ссылки
приложений, требования к HWID/особой авторизации, блокировки провайдера и
неработающие серверы требуют отдельной поддержки или действий у провайдера.
Другие протоколы, включая Trojan/VMess/Hysteria2, в этом изменении не добавлены.

Сложные цепочки proxy/detour, Xray Mux, произвольные stream/sockopt-настройки,
XHTTP downloadSettings и дополнительные варианты маскировки пока отклоняются.
Неизвестные параметры соединения не отбрасываются молча. Отключение проверки
TLS и импорт путей к сертификатам/ключам/логам службы не разрешаются.
packetaddr для маршрутов через Xray пока не поддерживается.

Из JSON/YAML импортируются только серверы. DNS, входящие порты, скрипты и
правила из чужой конфигурации не применяются. На Android новые возможности
не включены: его встроенный адаптер остаётся прежним.

## Проверка этой сборки

Пройдены Go-тесты всех пакетов с сетевыми build tags, включая:

- импорт и сохранение параметров, разделение корректных/некорректных узлов;
- автоматическое согласование формата с тестовым HTTPS-сервером;
- сохранение кэша и отсутствие ключей в ошибках;
- проверку шести синтетических конфигураций настоящим Xray v26.10.31;
- передачу HTTP через настоящий sing-box → SOCKS → Xray → XHTTP → локальный
  VLESS-сервер и завершение дочернего процесса при отключении;
- предварительную проверку смеси корректного узла и узла с неподдерживаемым
  шифрованием, при которой корректный узел остаётся доступен.

Системные маршруты и настройки действующего VPN при этих тестах не изменялись.
Установщик собран; его тесты пройдены. Вложенный ZIP и контрольные суммы
188 файлов комплекта, включая 17 файлов runtime, проверены. Отдельный IPC
smoke-test остановлен защитной проверкой из-за уже работающей службы Маршрута;
действующая служба не останавливалась и не обновлялась.
Реальное подключение TUN, переход между сетями, UDP/звонки и подписки сторонних
провайдеров требуют полевых испытаний. Локальный HTTP-тест не доказывает работу
любого внешнего сервиса или всех режимов XHTTP.

## Тестовый установщик

Локальная Windows 0.1.9 использует заново собранный из исходников интерфейс
Flutter 3.47.7 с редактором правил и обнаружением приложений, новое ядро из этой рабочей ветки и
закреплённый Xray из components.lock.json. Неизменённые нативный загрузчик
Flutter и DLL взяты из проверенного по SHA-256 установщика 0.1.7; версия
Flutter engine совпадает. В интерфейсе отображается 0.1.9, в отчёте есть
`compatibility_build: windows-applications-preview-1`. Это предварительная сборка,
не опубликованный GitHub-релиз. Правила: [ROUTING-RULES.md](ROUTING-RULES.md).

В среде сборки Windows Defender блокирует свежий архив zapret2. Защита не
отключалась: для локального preview сохранены неизменённые компоненты runtime
из исходного установщика 0.1.7, проверенные также по его файловому манифесту.
Xray проверен по SHA-256 закреплённого официального релиза.

Для обычной полной сборки из исходников используется scripts/build.ps1 с
Flutter; scripts/package-runtime.py включает закреплённый Xray и лицензии
в комплект. Локальные ключи подписки и подписи APK не требуются для Windows.
